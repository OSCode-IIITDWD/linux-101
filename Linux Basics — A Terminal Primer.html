00 Setting Up WSL on Windows

WSL (Windows Subsystem for Linux) lets you run a native Linux environment directly inside Windows 10/11 with no virtual machine overhead. Your Windows files are available under /mnt/c/.

# 1. Open PowerShell as Administrator and install Ubuntu:
wsl --install

# 2. Restart your PC when prompted.

# 3. Open Ubuntu from Start, enter a username/password, and update:
sudo apt update && sudo apt upgrade -y

Passwords in the terminal are invisible while typing (no dots/asterisks). To open your Linux directory in Windows Explorer, run explorer.exe .

01 The Terminal Mental Model & Command Anatomy

In Linux, the terminal is a window running a shell (such as bash or zsh). The shell is a command language interpreter: it reads text commands typed by the user, finds the corresponding executable program in your system, executes it, and returns the output.

COMMAND STRUCTURE
command  -flags  --options=value  [arguments...]
  │        │            │               │
  │        │            │               └── Targets (files, paths, text)
  │        │            └────────────────── Long-form configuration flags
  │        └─────────────────────────────── Short switches (often clusterable: -la)
  └──────────────────────────────────────── The executable binary or builtin

Example: ls -l --sort=size /var/log executes ls, turns on long format (-l), orders results by file size (--sort=size), and targets the directory /var/log.

Understanding Paths: Absolute vs. Relative

Every single file and directory in Linux branches from a single unified root designated by a forward slash (/). Drives like C:\ or D:\ do not exist in Linux; secondary drives are simply mounted onto folders in the tree.

Path SymbolMeaningExample
/The Root directory — top of the entire system/etc/hosts
~Your user's home directory (e.g., /home/senku)~/Documents
.The current directory you are currently standing in./script.sh
..The parent directory one level above../sibling-folder
-The previous working directory (like a TV "back" button)cd -
Pro-tip on Spaces: Linux paths use spaces as command argument separators. If a folder is named Project Notes, reference it with quotes (cd "Project Notes") or escape the space with a backslash (cd Project\ Notes).

02 Navigating the Filesystem (pwd, cd, ls)

Moving through directories confidently is the foundational terminal skill. These three commands tell you where you are, move you elsewhere, and show you what is around you.

pwd — Print Working Directory

Outputs the exact absolute path of the directory your shell is currently operating inside.

$ pwd
/home/senku/projects/web-app

Flag to know: pwd -P resolves symbolic links to reveal the actual physical hardware path.

cd — Change Directory

Changes the working directory of the shell session.

UsageDestination
cd or cd ~Jumps straight to your personal home directory (/home/username)
cd ..Climbs up one folder into the parent directory
cd ../..Climbs up two folder levels in one jump
cd -Toggles back to the directory you were in right before the last cd
cd /var/logNavigates to an absolute path, regardless of where you currently stand

ls — List Directory Contents

Without arguments, ls lists file and folder names in your current directory. With flags, it becomes one of the most informative diagnostic utilities in Linux.

ANATOMY OF ls -la OUTPUT
-rw-r--r--   1  senku  developers   4096  Sep 23 10:15  config.json
drwxr-xr-x   3  senku  developers   4096  Sep 23 10:14  src/
│└────┬───┘  │    │        │          │        │           │
│     │      │    │        │          │        │           └── File / Directory Name
│     │      │    │        │          │        └────────────── Last Modified Timestamp
│     │      │    │        │          └─────────────────────── Size in bytes (use -h for KB/MB)
│     │      │    │        └────────────────────────────────── Owning Group
│     │      │    └─────────────────────────────────────────── Owning User
│     │      └──────────────────────────────────────────────── Number of hard links
│     └─────────────────────────────────────────────────────── Permissions (Owner | Group | Other)
└───────────────────────────────────────────────────────────── Entry type (- = file, d = directory, l = symlink)

Essential ls Flags

FlagDescription & Why It Matters
-lLong listing: displays permissions, owner, group, size, and modification date.
-aAll files: includes hidden files (files beginning with a dot ., like .env or .bashrc).
-hHuman readable: formats byte counts into 4K, 25M, 2.1G (used alongside -l).
-tTime sort: sorts entries by modification time, newest first.
-rReverse: reverses whichever sorting order is active (e.g., ls -ltr puts newest files at bottom).
-RRecursive: lists contents of all subdirectories down the entire tree.
Daily Driver Habit: Use ls -lah as your standard listing command. It shows hidden configuration files, full permissions, and human-friendly file sizes.

03 Creating, Copying, Moving & Deleting

touch — Create Empty Files or Update Timestamps

The fastest way to generate empty placeholder files or trigger file watchers.

# Create one or multiple new empty files
$ touch index.html styles.css app.js

# If the file already exists, touch updates its modification time to right now
$ touch existing-file.txt

mkdir — Make Directories

Creates new folders on the filesystem.

# Basic directory creation
$ mkdir project

# -p (parents): creates intermediate missing directories without failing
$ mkdir -p backend/src/controllers/auth

# -v (verbose): tells you what it created
$ mkdir -pv api/v1/routes
mkdir: created directory 'api'
mkdir: created directory 'api/v1'
mkdir: created directory 'api/v1/routes'

cp — Copy Files & Directories

Duplicates files or folders from a source to a destination.

Command / FlagsAction & Explanation
cp file.txt copy.txtCopies file.txt to copy.txt in the current folder.
cp file.txt ~/backup/Copies file.txt into the backup folder, keeping the same name.
cp -r src/ dist/Recursive: Required when copying directories and all nested contents.
cp -i file.txt target.txtInteractive: Prompts you before overwriting an existing destination file.
cp -p file.txt backup.txtPreserve: Preserves original timestamps, file ownership, and permissions mode.
cp -u source/ dest/Update: Copies only files that are newer than destination files or missing.

mv — Move or Rename

In Linux, renaming a file and moving a file are the identical operation: updating the inode's directory path entry.

# Renaming a file in the same folder
$ mv draft.md post.md

# Moving a file to a new folder
$ mv post.md ~/blog/posts/

# Moving and renaming simultaneously
$ mv post.md ~/blog/posts/published-post.md

# Safe flag: -i asks before clobbering an existing file
$ mv -i config.json old-config.json

rm — Remove Files & Directories

Permanently deletes files and folders from the storage filesystem.

# Remove a single file
$ rm notes.tmp

# Remove a directory and all its recursive contents (-r)
$ rm -r old-build/

# Force removal (-f): suppresses confirmation prompts and ignores nonexistent files
$ rm -rf cache/

# Interactive removal (-i): prompts for confirmation before every file
$ rm -ri important-folder/
DANGER ZONE — No Recycle Bin: Unlike graphical operating systems, the Linux terminal provides no Trash or Recycle Bin by default. When rm executes, storage blocks are marked free and data is unlinked. Never run rm -rf /, and beware of rogue spaces in globs (e.g., typing rm -rf / tmp/test instead of rm -rf /tmp/test would wipe your root drive).

04 Reading & Inspecting File Contents (cat, less, head, tail, wc)

cat — Concatenate & Display

Reads files sequentially and writes them to standard output. Best suited for short files (1–50 lines).

# Dump file contents into terminal
$ cat /etc/os-release

# Display line numbers (-n)
$ cat -n server.py

# Concatenate multiple files into a single destination file
$ cat header.html body.html footer.html > index.html

less — Paginated File Inspection

Opens files in an interactive buffer without loading the entire file into RAM. Essential for viewing large logs, configuration files, and source code.

$ less /var/log/syslog
NAVIGATING INSIDE less
KeyAction
Space or fScroll forward one full window screen
bScroll backward one full window screen
j / ↓Scroll down one single line
k / ↑Scroll up one single line
gJump immediately to the first line of the file
GJump immediately to the last line of the file
/pattern + EnterSearch forward for text match
n / NJump to next / previous search match
qQuit less and return cleanly to your prompt

head & tail — Viewing Ends of Files

Inspect the start or tail end of files without opening a full viewer.

# View the first 10 lines (default)
$ head nginx.conf

# View the first 25 lines (-n 25)
$ head -n 25 /etc/passwd

# View the last 15 lines of a file
$ tail -n 15 production.log

# -f (follow): streams new lines live as other processes append to the file!
$ tail -f /var/log/nginx/access.log

wc — Word, Line & Byte Counter

$ wc -l words.txt       # count lines
$ wc -w essay.md        # count words
$ wc -c payload.bin     # count bytes

05 Streams, Redirection & The Power of Pipes

The Unix philosophy states: "Write programs that do one thing and do it well. Write programs to work together. Write programs to handle text streams."

Every process launched by the shell starts with three file descriptors automatically open:

StreamFile DescriptorDefault Destination
Standard Input (stdin)0Your keyboard input
Standard Output (stdout)1Your terminal screen
Standard Error (stderr)2Your terminal screen (reserved for errors & warnings)

Redirection Operators

# 1. > Overwrite stdout to a file (creates file or destroys previous content)
$ echo "version=1.0" > config.env

# 2. >> Append stdout to a file (appends to end without wiping existing data)
$ echo "port=8080" >> config.env

# 3. < Feed a file into a command's stdin
$ sort < unsorted-names.txt

# 4. 2> Redirect standard error only to an error log
$ find / -name "*.conf" 2> errors.log

# 5. &> or 2>&1 Redirect BOTH stdout and stderr into one single file
$ npm run build > build.log 2>&1

# 6. /dev/null — The system black hole: discard unwanted output completely
$ command-with-noisy-output > /dev/null 2>&1

The Pipe Operator (|)

The pipe takes the standard output of the command on its left and connects it directly into the standard input of the command on its right. You can chain as many commands as needed to build powerful real-time data pipelines.

PRACTICAL PIPELINE EXAMPLES
# Count how many system users have /bin/bash as their shell
$ cat /etc/passwd | grep "/bin/bash" | wc -l

# Extract unique IP addresses from a web log and count occurrences
$ cat access.log | cut -d' ' -f1 | sort | uniq -c | sort -nr | head -n 5

# tee: print output to terminal AND save it to a file simultaneously
$ make test 2>&1 | tee test-results.log

06 Searching Files & Content (grep, find, which)

grep — Search Inside File Contents

Scans files for lines matching regular expressions or plain string patterns.

# Basic search inside a specific file
$ grep "DATABASE_URL" .env

# -i (ignore case)
$ grep -i "error" /var/log/syslog

# -r or -R (recursive): search all files in current directory and subdirectories
# -n (line number): display the exact line number of every match
# -I (ignore binary files like compiled assets or images)
$ grep -rnI "SECRET_KEY" .

# -v (invert match): output lines that do NOT contain the pattern
$ grep -v "^#" config.conf   # strips out comment lines starting with #

# -c (count): returns the number of matching lines
$ grep -c "404" access.log

# -E (extended regex): search for multiple alternate patterns
$ grep -E "FATAL|CRITICAL|PANIC" app.log

find — Search Directory Trees for Files by Metadata

Unlike grep which searches file contents, find traverses directory trees looking for file system nodes based on filename, size, age, or permissions.

Example QueryWhat It Does
find . -name "*.js"Finds all files ending in .js from the current folder down.
find . -iname "readme*"Case-insensitive search (matches README.md, readme.txt).
find /var/log -type f -name "*.log"Restricts search to regular files (-type f), ignoring folders.
find . -type d -name "node_modules"Finds directories only (-type d).
find . -size +100MFinds all files strictly larger than 100 Megabytes.
find . -mtime -3Finds files modified within the last 3 days.
find . -name "*.tmp" -deleteFinds all temporary files and immediately deletes them.
find . -name "*.log" -exec gzip {} \;Runs a shell command on every discovered match ({} is replaced by file path).

which & whereis — Locating Commands

# which: reveals which executable binary runs when you type a command (checks $PATH)
$ which node
/usr/local/bin/node

# whereis: finds the binary, source code, and manual page locations
$ whereis python3
python3: /usr/bin/python3 /usr/lib/python3 /usr/share/man/man1/python3.1.gz

07 Permissions & Ownership (chmod, chown, sudo)

Linux is a multi-user operating system with a strict access control matrix. Every file and directory is owned by one User and assigned to one Group.

PERMISSION TRIPLETS DECODED: -rwxr-xr--
ClassLettersNumeric ValueMeaning
User (Owner)rwx4 + 2 + 1 = 7Read, Write, and Execute privileges
Groupr-x4 + 0 + 1 = 5Read and Execute privileges (no write/edit)
Others (World)r--4 + 0 + 0 = 4Read only (cannot edit or execute)

What x (execute) means on a directory: You cannot cd into a directory or read files inside it without the execute bit!

chmod — Change File Mode / Permissions

Can be executed using numeric octal notation or symbolic notation.

Octal Notation

chmod 755 script.sh
User: rwx (7), Group: rx (5), Others: rx (5). Standard for scripts & executables.

chmod 644 file.txt
User: rw (6), Group: r (4), Others: r (4). Standard for documents & web assets.

chmod 600 id_rsa
User: rw (6), Group: 0, Others: 0. Private keys; no one else can read.

chmod -R 755 /var/www
Applies permissions recursively to all nested files and folders.

Symbolic Notation

chmod +x deploy.sh
Adds execute permission for everyone.

chmod u+w file.txt
Grants write permission to the file owner (user).

chmod go-rwx secret.env
Revokes all permissions from group and others.

chmod a=rw shared.txt
Sets read/write for all (user, group, and others).

chown — Change Ownership & Group

Requires administrative permissions (via sudo).

# Change the owner of a file
$ sudo chown senku app.py

# Change both user owner and group owner at once (user:group)
$ sudo chown senku:developers /opt/project

# Recursively change ownership for an entire directory tree (-R)
$ sudo chown -R www-data:www-data /var/www/html

sudo & Superuser Privileges

sudo (SuperUser DO) allows authorized users to run security-sensitive commands as root (the all-powerful system administrator).

# Update package repositories (requires root)
$ sudo apt update

# Re-run your last command with sudo if you forgot it (lifesaver!)
$ sudo !!

# Spawn a full interactive root shell (use sparingly!)
$ sudo -i

kill & pkill — Terminating Processes

Processes are stopped by sending them asynchronous Unix signals.

CommandSignalBehavior
kill 1420SIGTERM (15)Graceful: Asks the process to safely flush buffers, close database handles, and exit cleanly.
kill -9 1420SIGKILL (9)Forceful: The Linux kernel immediately nukes the process memory. Cannot be caught, handled, or blocked. Use only when process hangs.
killall nodeSIGTERM (15)Terminates all processes matching the binary name node.
pkill -f "worker.py"SIGTERM (15)Matches and kills processes based on full command-line arguments.

09 Networking & Remote Transfers (ping, curl, ip, ss)

ping — Test Network Latency & Reachability

# Linux ping runs forever until interrupted! Always use -c to set packet count
$ ping -c 4 google.com
PING google.com (142.250.190.46) 56(84) bytes of data.
64 bytes from ... icmp_seq=1 ttl=117 time=12.4 ms
--- google.com ping statistics ---
4 packets transmitted, 4 received, 0% packet loss

curl — Transfer Data Across URLs

The standard tool for interacting with REST APIs, testing web servers, and downloading assets.

# Simple GET request dumped to stdout
$ curl https://api.github.com/zen

# -I (head): Fetch HTTP response headers only (status code, content-type, server)
$ curl -I https://example.com

# -O (remote name) & -L (follow redirects): Download file and save with original filename
$ curl -LO https://github.com/torvalds/linux/archive/refs/tags/v6.8.tar.gz

# -d (data) & -H (header): Send JSON payload via HTTP POST
$ curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -d '{"name": "Senku", "role": "engineer"}'

ip & ss — Network Interfaces & Sockets

# ip addr (or ip a): Display IP addresses and active network interfaces
$ ip a

10 The Linux Filesystem Hierarchy Standard (FHS)

Unlike Windows drive letters (C:, D:), every resource in Linux is unified under root (/). Understanding where files live allows you to find configs, logs, and devices instantly.

/ (Root Directory) ├── bin → Essential system command binaries (ls, cp, rm, bash) ├── boot → Linux kernel, initramfs images, and GRUB bootloader ├── dev → Device nodes representing hardware (/dev/sda disk, /dev/null, /dev/random) ├── etc → System-wide configuration files (nginx.conf, passwd, hosts, fstab) ├── home → Personal user folders (/home/senku) containing documents, desktop, and configs ├── lib → Shared libraries and kernel modules required by system binaries ├── media → Auto-mounted removable storage media (USB drives, external SSDs) ├── mnt → Temporary manual mount points for sysadmins ├── opt → Optional add-on third-party software packages (e.g., /opt/google/chrome) ├── proc → Virtual pseudo-filesystem exposing real-time kernel data & process states ├── root → Home directory of the root user (separate from regular /home) ├── sbin → System administrative binaries (fdisk, reboot, iptables) ├── sys → Virtual pseudo-filesystem exposing kernel hardware devices & drivers ├── tmp → Temporary scratch files (automatically purged on reboot or timer) ├── usr → User utilities, applications, libraries, and documentation (/usr/bin, /usr/lib) └── var → Variable persistent data: logs (/var/log), mail, caches, and web roots (/var/www)

11 Terminal Muscle Memory & Superpowers

Fluency in Linux comes down to keyboard shortcuts and shell expansion techniques that eliminate tedious typing.

Key Navigation & Control Shortcuts

ShortcutAction
TabAutocomplete: Press once to complete a command or file path; press twice to show all matching choices.
Ctrl + CInterrupt (SIGINT): Aborts and kills the foreground program running right now.
Ctrl + ZSuspend (SIGTSTP): Pauses running program and sends it to background (type fg to resume).
Ctrl + LClear: Clears terminal screen while keeping your current command line intact.
Ctrl + RReverse History Search: Start typing any word to recall past commands from history!
Ctrl + AJump cursor to the beginning of the command line.
Ctrl + EJump cursor to the end of the command line.
Ctrl + UDelete everything from the cursor back to the start of the line.
Ctrl + KDelete everything from the cursor forward to the end of the line.
Ctrl + WCut the single word immediately preceding the cursor.

Shell Expansion Shortcuts

# 1. !! — Rerun the exact previous command
$ apt update           # Fails: Permission denied
$ sudo !!              # Reruns as: sudo apt update

# 2. !$ — Reuses the last argument from previous command
$ mkdir -p /var/www/my-new-site
$ cd !$                # Expands to: cd /var/www/my-new-site

# 3. Brace Expansion {} — Generate multiple targets rapidly
$ touch file_{1..5}.txt          # Creates file_1.txt, file_2.txt ... file_5.txt
$ cp config.json{,.bak}          # Duplicates config.json to config.json.bak
$ mkdir -p app/{src,tests,dist}  # Creates app/src, app/tests, and app/dist

12 Guided Hands-on Practice Lab

Type and execute each step sequentially in your terminal. This exercises the full lifecycle: directory management, file creation, writing, permissions, pipelines, searching, inspection, and clean removal.

# Step 1: Create a sandbox directory and step inside
$ mkdir -p ~/linux-lab/data && cd ~/linux-lab

# Step 2: Generate sample data files
$ echo "alpha error: connection timeout" > data/log1.txt
$ echo "beta info: service started"     > data/log2.txt
$ echo "gamma error: disk full"         >> data/log1.txt

# Step 3: Inspect directory with full metadata
$ ls -lah data/

# Step 4: Search for errors across all files recursively
$ grep -rnI "error" data/

# Step 5: Pipe, sort, and count lines
$ cat data/log1.txt data/log2.txt | grep "error" | wc -l

# Step 6: Create an executable script
$ echo 'echo "Hello from Linux Lab $(date)"' > run.sh

# Step 7: Grant execute permission and run it
$ chmod +x run.sh && ./run.sh

# Step 8: Verify active disk usage of our sandbox
$ du -sh ~/linux-lab

# Step 9: Clean up completely
$ cd ~ && rm -rf ~/linux-lab

RULE №1 OF THE TERMINAL: Always read and understand a command before pressing Enter — especially with sudo, rm, or redirection operators.
